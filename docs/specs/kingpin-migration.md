# Migrating clip's CLI from cobra/viper to kingpin v2

clip's command line is built on `github.com/alecthomas/kingpin/v2`
with a small YAML configuration layer on `gopkg.in/yaml.v3`. The stack it
replaces is `spf13/cobra` + `spf13/viper` + `mitchellh/go-homedir`. This
document records what changed, how the two differ for users and for the code,
and the reasons behind the design choices.

## Repository layout

Before:

```
main.go               cobra entry point
cmd/root.go           root command, persistent flags, viper initialization
cmd/<command>.go      one cobra.Command per subcommand, logic in Run closures
helpers/template.go   template file type, load and render (reads viper for global vars)
helpers/utilities.go  string helpers
helpers/yaml.go       yaml helpers
```

After:

```
cmd/clip/main.go            parse, dispatch, report errors
internal/cli/cli.go         application construction, Run dispatch, config resolution, template lookup
internal/cli/<command>.go   one file per subcommand: registerXxxCmd and runXxx
internal/config/            Config type, Load, EnsureConfigFile, EnsureTemplateDir, Resolve
internal/template/          File, Load, Render
internal/version/           Version, BuildDate, Commit, Print
```

The binary moves to `cmd/clip` so the module root holds no `main` package.
Everything else is `internal` because clip exports no library API. All files
carry the repository's MIT license header.

## Command surface

| Before (cobra) | After (kingpin) |
|---|---|
| `clip` runs `list` | `list` is the kingpin default command (`.Default()`); bare `clip` still lists |
| `clip <template>` runs `copy <template>` | removed; copying is `clip copy <template>` |
| `copy` (aliases `load`, `in`), optional template argument, stdin without one | same; `cmd.Arg("template").String()` |
| `create` (`add`, `make`), one argument | same; `Required()` argument |
| `edit`, one argument, `-e/--editor` | same; the flag help describes the editor (the cobra text was a copy of the template-dir text) |
| `list`, `--tags`, `--tags-only` with `--list-tags` and `--show-tags` as equivalents | same; `--tags` accepts `a,b` and repeated flags; `--list-tags`/`--show-tags` still accepted but hidden from help |
| `paste` (`out`, `print`) | same |
| `remove` (`delete`), one argument | same |
| `rename` (`move`), two arguments | same; refuses to overwrite an existing destination |
| `show` (`cat`, `dump`), one argument | same |
| `version`, `-v/--version` | same; both print `version.Print` output |
| `--config` persistent flag | app-level `--config` |
| `-t/--templatedir` persistent flag | app-level `-t/--template-dir`; `--templatedir` kept as a hidden flag bound to the same variable |
| `clip help [cmd]`, `clip <cmd> --help` | kingpin built-ins |
| `clip completion <shell>` (generated by cobra, undocumented) | kingpin's hidden `--completion-script-bash` / `--completion-script-zsh` |

### Root invocation

kingpin allows one default command per level. When the first word is not a
command name, the parser selects the default command without consuming the
word and then parses the word as that command's argument. `list` takes no
arguments, so `clip foo` is a parse error (`unexpected foo`). `clip --tags a,b`
parses as `list --tags a,b` because an app-level flag the application does not
own falls through to the default command's flags the same way.

Reproducing the cobra `clip <template>` shortcut on top of this needs a
rewrite of argv before kingpin sees it: find the first positional word, which
means re-implementing kingpin's flag lexing (`--flag value`, `--flag=value`,
`--no-flag`, `-x`, clustered boolean shorts, `-tVALUE`), decide whether the
word names a command or alias, and insert `copy`. The same rewrite collides
with shell completion, whose scripts pass the partial word as a positional
token. The shortcut is dropped instead, and the `copy` help text no longer
advertises it.

### Flag lexing differences

kingpin accepts `--no-<flag>` for every boolean flag and lists them as
`--[no-]help` in usage. Repeated string flags accumulate (`--tags a --tags b`)
instead of replacing, so `--tags` is registered with `Strings()` and each value
is split on commas at use.

kingpin expands an argument of the form `@file` into the file's contents by
default (`kingpin.EnableFileExpansion`). A template name is never a file
reference, so expansion is disabled in `NewApp`.

### Shell completion

kingpin's completion scripts call `clip --completion-bash <words typed so far>`
with the word under the cursor last, and filter clip's output by that word
themselves (`compgen -W`, `compadd`). In kingpin v2.4.0 the parser assigns the
command names as completion alternatives when it selects the default command
for an unmatched word, then clears them before moving on (`parser.go`,
`TokenArg` branch), so only the end-of-input path yields command names.
`cli.CompletionArgs` drops the partial word from a completion request before
parsing; kingpin then offers every command and the shell narrows the list.
Flag completion (`--te<Tab>`) does not go through that branch and works
unchanged.

## Behavior differences

| Area | Before | After | Why |
|---|---|---|---|
| Failures | printed to stdout, exit 0 | stderr, exit 1, prefixed `clip: error:` like kingpin's parse errors | scripts can detect failure; `main` reports handler errors through `app.Fatalf` so the prefix is uniform |
| "template not found", "already exists" | stdout notice, exit 0 | errors like any other failure | same |
| First-run notices (config file written, template directory created) | stdout | stderr | a piped `clip paste` or `clip show` must not carry notices in its output |
| Version output | one line | multi-line `version.Print` for `--version`, `-v`, and `version` | one formatter for both paths; builds without ldflags fall back to `debug.ReadBuildInfo` (module version, `vcs.revision`, `vcs.time`) so no field is blank |
| Config `templatedir` key | silently ignored (see below) | honored | explicit precedence resolution |
| Config `templatedir` value | literal | a leading `~/` expands to the home directory | yaml does not expand `~`, and the config file is the one place a user types a home-relative path |
| First-run config file | `editor`, `templatedir`, `vars` pinned to resolved absolute values | commented scaffold pinning `editor` and `vars`, `templatedir` commented out | with the key live, a pinned absolute `$HOME/clip` from the first machine would break the file when synced to another; left unset it resolves per machine |
| Config `vars` keys | lower-cased by viper | case-sensitive as written | yaml.v3 unmarshals keys verbatim; templates reference vars by their written name |
| `TEMPLATEDIR` environment variable | nominally read by viper's `AutomaticEnv`, never effective (same bug as the config key) | not read | no `CLIP_*` environment surface; `$EDITOR` is the only environment input and is resolved explicitly |
| Template names | top-level `.yml` only; `.yaml` and nested files were listed but not addressable | path relative to the template directory without `.yml`/`.yaml` (`work/standup`); `create` makes subdirectories | one naming rule shared by `list` and every other command |
| Template names that escape the directory (`../x`, `/abs`) | accepted | rejected (`filepath.IsLocal`) | a template name is a key, not a path |
| `rename` onto an existing template | printed "No action taken" and renamed anyway | refuses; keeps the source extension | correctness |
| `edit` positional argument | taken from `os.Args[len-1]`, so `clip edit foo -e vim` edited `vim` | taken from the parser | correctness |
| `edit` with `$EDITOR="code --wait"` | `exec.LookPath` on the whole string failed | split into argv; the editor is resolved before the template is scaffolded | a failing editor must not leave an empty template behind |
| `clip <template>` | copied the template | parse error; `clip copy <template>` | see Root invocation |
| `list --tags <tag>` | matched when `<tag>` was a substring of a template's tag (`go` matched `golang` and `django`) | matches whole tags only | the help text and README only ever show whole tags; substring hits were surprises, and a prefix lookup has no way to opt out of them |
| `clip ""` | copied stdin | parse error | follows from the above |
| `@name` as an argument | plain template name | plain template name | `EnableFileExpansion` off |
| Help layout | cobra | kingpin; aliases are not shown inline, the README carries the alias table | |

### The dead `templatedir` config key

`cmd/root.go` called `viper.Set("templatedir", <flag value or $HOME/clip>)`
before `viper.ReadInConfig()`. `viper.Set` has the highest precedence in
viper, above config-file and environment values, and ran even when the `-t`
flag was unset, so the documented config key could never take effect. The
replacement resolver has a regression test asserting that a config file's
`templatedir` wins over the built-in default.

## Architecture

### Application construction and dispatch

`cli.NewApp` builds a `kingpin.New` application (not the global
`kingpin.CommandLine`), sets the prologue in the required order (`Version()`
creates `VersionFlag`, so it precedes `VersionFlag.Short('v')`), registers the
app-level flags, and calls one `registerXxxCmd(app)` per command. Each register
function declares the command with its aliases, flags, and arguments, binds
them to package-level variables, and stores `cmd.FullCommand()` in a
package-level name.

`main` parses and calls `cli.Run(cmdName)`, which resolves configuration and
switches over the stored command names to the `runXxx(cfg) error` handlers.
Handlers return errors rather than printing them. No kingpin `Action`
callbacks are used: dispatch lives in one switch, and the handlers are plain
functions the tests call directly with a `config.Config`.

```go
func main() {
	app := cli.NewApp()

	args := os.Args
	if len(args) > 0 {
		args = args[1:]
	}
	cmdName := kingpin.MustParse(app.Parse(cli.CompletionArgs(args)))

	if err := cli.Run(cmdName); err != nil {
		app.Fatalf("%v", err)
	}
}
```

### Configuration

```go
// internal/config
type Config struct {
	Editor      string            `yaml:"editor"`
	TemplateDir string            `yaml:"templatedir"`
	Vars        map[string]string `yaml:"vars"`
}

type Flags struct{ Editor, TemplateDir string }

func DefaultPath(home string) string                          // $HOME/.clip.yml
func Load(path string) (Config, error)
func EnsureConfigFile(path string) (created bool, err error)  // commented scaffold, O_EXCL
func EnsureTemplateDir(path string) (created bool, err error)
func Resolve(flags Flags, getenv func(string) string, file Config, home string) Config
```

Precedence per setting, highest first; an empty value falls through:

| Setting | Order |
|---|---|
| config file path | `--config` > `$HOME/.clip.yml` |
| `editor` | `--editor` > `$EDITOR` > config file > `nano` |
| `templatedir` | `-t`/`--template-dir`/`--templatedir` > config file (`~/` expanded) > `$HOME/clip` |
| `vars` | config file > `{name: Clip User}` |

`Resolve` is a pure function of its inputs (`getenv` is injected), which is
what makes the precedence matrix table-testable. `cli.Run` resolves
configuration before dispatching any command, including `version` and `paste`,
so first-run creation of the config file and template directory happens on
whichever command runs first. Failure to create the template directory is a
warning at that point; commands that need the directory fail on it themselves.

### Templates

`internal/template` holds the `File` type (`tags`, `template.vars`,
`template.text`) and `Load`/`Render`. `Render(tmpl File, globalVars
map[string]string)` receives the config's `vars` as a parameter where the old
`helpers.ExecuteTemplate` read `viper.GetStringMapString("vars")` directly;
merge order is unchanged (template vars override globals). A malformed
template is a returned parse error where the old code used `template.Must` and
panicked. The sprout registries loaded are unchanged (every registry except
`backward`).

Template lookup in `internal/cli` tries `.yml` then `.yaml`; `create` writes
`.yml`; `rename` keeps the source extension.

### Version

`internal/version` exposes `Version`, `BuildDate`, and `Commit`, set with
`-ldflags -X`, and `Print(programName)` for the multi-line output.
`.goreleaser.yml` points `main` at `./cmd/clip` and the ldflags at
`github.com/tjhop/clip/internal/version.{Version,Commit,BuildDate}`. `Makefile`
targets are unchanged; `binary` runs goreleaser, which picks up the new paths.

| `internal/cli` `TestCompletionArgs` | which word a completion request drops |
| `internal/cli` `TestResolveConfig` | first-run creation under a throwaway `HOME`, config-file `templatedir` honored and `~/` expanded, flag over file, `$EDITOR` over file, `--editor` over `$EDITOR`, the `--config` path, a malformed file |
| `internal/cli` `TestHandlers` | `create` scaffold and no-overwrite, nested names, rejected names, not-found errors, `rename` extension and no-clobber, `edit` argv splitting and editor-before-scaffold, `copy` failing before the clipboard |
| `internal/cli` `TestListLines` | the naming rule, `.yaml` and nested discovery, whole-tag filtering, sorted deduplicated tags, a malformed template failing only when its tags are read |
| `internal/config` tests | the full precedence matrix, scaffold round-trip, `EnsureConfigFile` leaving an existing file alone |
| `internal/template` `TestRender`, `TestLoad` | var merging, sprout functions, parse and execute errors returned rather than panicking |

Handlers write through package-level flag variables, so the `internal/cli`
tests do not run in parallel and reset those variables between cases.

## Out of scope

- No `CLIP_*` environment variables. kingpin's `DefaultEnvars()` derives names
  from the application name and flag name only, so same-named flags on
  different subcommands would share one variable.
- No logging framework; clip prints results.
- No change to the template file format or the sprout registries. The
  clipboard library is replaced in its own change; see
  [clipboard-backend.md](clipboard-backend.md).
